# DRL for Musculoskeletal Control

Analysing the capabilities of deep reinforcement learning for musculoskeletal
control, comparing four algorithms: SAC, TD3, PPO and DDPG.

Can a neural network trained by reinforcement learning replace classical
calculation of the force required in each individual muscle during a reaching
movement?

**Short answer: for *which* muscles and in what proportion, yes. For *how much*
force, yes — but only once the reward actually asks for it. For speed, no.**

This repository contains the model, the training and analysis pipeline, every
measured result, and a fully rewritten thesis report. It also documents six
substantive defects found during development, four of which produced entirely
believable results while being wrong.

---

## Headline results

All figures are means over **five training seeds × three target seeds** unless
stated. Intervals combine both components: an audit found that the target draw
contributes as much variance as the training seed, and earlier versions of this
work reported only the latter (see `thesis_report/` §5.4).

| Result | Value |
|---|---|
| Reaching error (hand to target, end of 2 s reach) | **0.1074 ± 0.0079 m** |
| Closest approach | **0.0734 ± 0.0058 m** |
| Agreement with static optimisation (Pearson *r*) | **0.808 ± 0.044** |
| Muscular effort vs the classical optimum | **1.91 ± 0.15 ×** |
| …vs the *achievable* floor a conventional controller reaches (1.33) | ≈ 44 % above |
| **…with the effort term weighted appropriately (w₂ = 20)** | **1.34 ×, i.e. at the floor** |
| Blow-up rate | 0 % in all runs |

The excess effort is anatomically localised: the three deltoids agree with the
classical solution to within 2.5–10 % NRMSE, while the lateral and medial heads
of triceps are driven at **3–4.5×** the prescribed force — sustained
co-contraction against the biceps. Three methodologically unrelated analyses
(effort ratio, co-contraction index, muscle-synergy decomposition) locate the
same defect in the same muscles.

### Two claims withdrawn from the earlier version of this work

- **A 7.3× latency advantage.** It timed the wrong computation (forward-simulation
  equilibrium, not load sharing) and compared two unoptimised Python
  implementations. Measured like-for-like, a direct solve of the load-sharing
  problem runs in **24 µs** against the network's **289 µs** — the classical
  method is about an order of magnitude *faster*.
- **A four-algorithm benchmark with significance tests.** Those numbers were
  generated by `numpy.random.normal`, not by experiment. See
  `thesis_report/` conclusion, "Results withdrawn from the previous version".

## Reproducing

```bash
pip install -r requirements.txt
python run_benchmark.py        # five configurations × three seeds
python force_comparison.py     # the central analysis
python run_conventional.py     # classical controller baseline
```

Tested on Python 3.12 with MuJoCo 3.7.0, Stable-Baselines3 2.8.0, PyTorch 2.11.0
(CPU). Model weights and replay buffers are excluded from version control; runs
regenerate them.

## What this work does *not* establish

Stated here because it matters more than the headline numbers.

- **No ground truth.** Everything is simulated. Both the learned solution and the
  classical reference are computed inside MuJoCo, against MuJoCo's muscle model.
  No electromyography, no measured force, no human subject.
- **The force comparison is conditional.** Static optimisation is handed the
  movement the policy produced and asked only how to distribute force across it.
  It validates load sharing *along a trajectory*, not the trajectory itself.
- **No significance testing.** Three seeds for the algorithm comparison, five for
  the main result. No *p*-value is reported anywhere, deliberately.
- **The strict success criterion is essentially unmet** (0–20 % depending on
  seed — a twentyfold spread that identifies it as noise). A privileged
  controller with full state access meets it only ~7 % of the time.
- **The model is heavily reduced.** Nine muscles; the rotator cuff is absent,
  which required constraining shoulder rotation.
- **The cause of the precision plateau is the discount factor.** One-at-a-time
  ablation over all five tuned hyperparameters: γ recovers 106 % of the
  default-to-tuned interval, the other four recover nothing. An earlier
  attribution to the exploration temperature was tested and refuted.
- **The parallel elastic element never engages** — passive force is exactly zero
  in every sampled state, so the "complete Hill model" describes the model file
  rather than what is active in simulation.
